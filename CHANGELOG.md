## [0.2.0](https://github.com/cafercangundogdu/nestjs-zod-openapi/compare/v0.1.0...v0.2.0) (2026-09-09)

### ⚠ BREAKING CHANGES

* `engines.node` is now `>=22.12.0`. Node 20 is EOL, and 22.12 is the minimum NestJS 12 supports.

### Features

* NestJS 12 support alongside 11 — the `@nestjs/common` and `@nestjs/swagger` peer ranges are now `^11.0.0 || ^12.0.0`, and `SUPPORTED_SWAGGER_MAJORS` covers both. NestJS 12 ships ESM-only packages; both the CommonJS and ESM builds of this library work with it unchanged, because Node loads the `@nestjs/*` internals through `require(esm)`.
* `createStandardSchemaConverter()` — a `standardSchemaConverter` for `SwaggerModule.createDocument()` on `@nestjs/swagger` 12. It renders Zod schemas passed to `@Body({ schema })`, `@Query({ schema })`, `@Param(name, { schema })` and `@ApiResponse({ standardSchema })` through zod-to-openapi with the library's post-processing: `.openapi('Name')` → `$ref` plus a component, nested named components, `discriminatedUnion` → `oneOf` with `discriminator`, `z.coerce.date()` → `string` / `date-time`, spurious `nullable` stripped, and `pattern` derived from format checks. Non-Zod Standard Schemas fall back to NestJS's built-in conversion.
* `patchNestSwagger()` injects that converter automatically; a converter passed to `createDocument()` by the app always wins. New option `standardSchemaConverter?: StandardSchemaConverter | false` overrides or opts out.
* On `@nestjs/swagger` 12, `patchNestSwagger()` also wraps `SchemaObjectFactory.prototype.getSchemaOverride` so an unnamed `@Query({ schema })` / `@Param({ schema })` with a named object schema still expands into individual parameters.
* `ZodValidationPipe` in global mode validates a Zod schema attached to the parameter decorator (`ArgumentMetadata.schema`, NestJS 12). Precedence: constructor schema → decorator schema → `createZodDto()` metatype → pass through; non-Zod Standard Schemas pass through.
* New type exports: `StandardSchemaConverter`, `StandardSchemaConversionResult`.

### Bug Fixes

* Scalar root schemas — for example `@Param('id', { schema: z.string().uuid() })` — now receive the `nullable` and `pattern` post-processing that object schemas already got.

### Miscellaneous

* Bumped `@asteasolutions/zod-to-openapi` to `^9.1.0` (new string formats, nested `discriminatedUnion` mapping fix) and `openapi3-ts` to `^4.6.1`.
* Verified against Zod 4.5.x; the peer range stays `zod ^4`.
* Shared helpers extracted into `src/zod-introspection.ts` and `src/openapi-fixes.ts`. No public API change.
* The test runner moved from Jest to Vitest, with `unplugin-swc` for decorator metadata.
* The CI matrix is now Node 22/24 × NestJS 11/12, and the publish workflow runs on Node 22.
* Releases are automated with release-please: it maintains the release PR, tag, GitHub release and changelog; the publish workflow only publishes to npm.
* pnpm enforces a 7-day `minimumReleaseAge` supply-chain policy — mirroring Dependabot's cooldown — and the dev toolchain is pinned to releases that satisfy it.
